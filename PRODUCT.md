# SubLane

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

A modular Go monolith with chi, sqlc-generated database queries, SQLite, and an embedded static frontend. The frontend uses the user-selected Shadcn Admin, React, TypeScript, Vite, TanStack Router, and TanStack Query. A provider adapter reuses CLIProxyAPI v8.0.35’s built-in executors while SubLane owns OAuth, encrypted storage, refresh, account selection, and the public HTTP boundary.

## Users

Platform operators, workspace owners, workspace administrators, and members. One login identity may belong to several workspaces with different roles. Workspace administrators manage their own subscription accounts, API channels, resource groups, members, and allowances; members use personal gateway keys.

## Product Purpose

Client-initiated model changes with complete portable history can replace a conversation's account binding when its account does not support the new model. The gateway persists the normalized model with each binding and rechecks the destination's pool, model policy, quota and capacity. Unchanged models, incremental WebSocket turns and opaque provider continuations never trigger account failover. Existing bindings without recorded model metadata retain their original account until a supported request establishes that metadata.

Codex automatic approval reviews use consistent parent-thread metadata as an account preference within the authenticated user and resource group. Existing child bindings remain authoritative. New review requests prefer the parent account only after the same capability, permission, quota, allowance and capacity checks as other candidates. Missing, ambiguous, expired or unavailable parents fall back to normal scheduling without changing the parent's binding. Synthetic HTTP and WebSocket tests cover routing and authorization; live Codex-client acceptance remains unverified.

Antigravity model discovery retains account-advertised internal models as callable capabilities while omitting `isInternal` entries from client model lists and picker suggestions. Authenticated browser model catalogs list these entries with a localized hidden-model label. Internal per-model quota observations are retained in memory and SQLite for admission and freshness, while usage responses hide them without mutating the shared snapshot. Exhausted internal models are rejected before inference, including after restart; unknown or reset quota retains the existing admission rules and unrelated models stay eligible. Explicit requests retain existing model policies, group/key authorization, quota, capacity and account lifecycle checks. Older catalogs refresh automatically to acquire visibility metadata. A data-preserving migration expands bounded quota snapshots to 256 KiB for the existing 512-model catalog limit. Synthetic discovery, quota-refresh-to-forwarding, migration, restart and native Gemini HTTP tests cover this behavior; live subscription acceptance remains unverified.

Build a minimal gateway that can host several isolated workspaces in one Go process and SQLite database. Keep a single-workspace self-hosted installation simple while supporting a hosted multi-tenant deployment. Codex, Claude, Antigravity and Grok Build subscription providers are enabled. Official OpenAI and third-party OpenAI-compatible Chat Completions APIs support administrator-configured API keys and base URLs.

Subscription accounts and API channels have separate management contracts and pages. Subscription accounts use OAuth and credential imports at `/accounts`; API channels use API keys and base URLs at `/channels`, with administrator-only `/api/channels` endpoints and a channel-specific status model. API channel responses contain no subscription identity, plan or token-expiry fields. Both reuse the existing encrypted execution resource owner, immutable IDs, proxy bindings, catalogs, concurrency, affinity and request accounting. Existing gateway keys and resource relationships are retained; no credentials are moved into the SDK store.

Resource groups replace the account-pool management concept. They select typed subscription/channel resources, model policies and member grants. Existing `account_ids` management payloads remain compatible, while the UI sends typed `resources`. New UI groups default to subscriptions first with API fallback disabled; API-only groups use their explicitly selected channels. Administrators can prefer API channels or retain protocol preference. Upgrades preserve existing groups' protocol preference and enabled fallback. Selection ranks only eligible resources, applies the same fallback policy to discovery, availability, readiness and alerts, and never moves existing conversation bindings in response to availability changes. Disabling API fallback may block an existing API-bound conversation rather than switch its source.

API model discovery reads the configured base URL's `/models` endpoint. The pinned public SDK OpenAI-compatible executor converts client protocols to upstream Chat Completions, using ephemeral execution auth. Static keys never enter OAuth refresh; key replacement preserves channel identity and endpoint, while changing the endpoint requires a separate channel. Native names such as `openai/model` remain intact during model policy checks. API balances and subscription quotas are unavailable; compaction remains Codex-only. Synthetic tests cover channel/resource management and routing; real API services require separate acceptance.

## Capabilities and Constraints

Workspace administrators can immediately remove ordinary members, and workspace owners can also remove administrators. Owners and the acting administrator cannot be removed. Removal hides the membership from the roster, denies workspace access, clears that workspace's resource-group grants, and permanently revokes its personal API keys and encrypted key values in one audited transaction. Global identities, sessions, other workspaces, request history, usage, and allowance ledgers are retained. In-flight requests can finish and settle; subsequent requests and WebSocket turns recheck access. Removed members can explicitly rejoin through Add existing account with fresh membership settings, new keys, and new resource grants; same-window allowance usage is preserved. Historical allowance details mark removed members. An additive migration records removal on the workspace membership, independently of history retention.

Every login identity can enable authenticator TOTP with ten single-use recovery codes and register up to ten user-verified, discoverable passkeys in personal preferences. Password sign-in enforces the enrolled factor; passkeys support passwordless sign-in. TOTP secrets use user-bound vault encryption; recovery codes and browser challenge tokens are stored only as digests. Security changes revoke other browser sessions and invalidate pending enrollment, while local administrator recovery clears lost factors and passkeys. Regular password changes and remote member resets preserve factors. Backups validate TOTP encryption and restore credentials without pending browser challenges. Credential keys can be placed outside the data directory with the optional SUBLANE_CREDENTIALS_KEY_FILE setting; legacy placement remains the default. New CLI and web backups require a separate 12–128-character password and stream the existing archive through age encryption. External keys are never copied into export staging. Verification and restore accept historical plaintext archives with an explicit legacy status; encrypted inputs have bounded KDF work and must authenticate through EOF before publication. Restore still prepares a private new directory; operators using external keys move the recovered key to a new external path before activation. A local Linux rootful Compose migration helper checks the running data mount and credential-key identity, preserves Compose interpolation, verifies encrypted backups before and after old-key removal, and retains private configuration recovery with automatic and explicit rollback.

Optional instance-wide scheduled encrypted backups use `SUBLANE_BACKUP_DIR` and a private regular `SUBLANE_BACKUP_PASSWORD_FILE`, with `SUBLANE_BACKUP_INTERVAL` (24h by default, 1h–720h) and `SUBLANE_BACKUP_KEEP` (7 by default, 1–365). The process runs one backup at startup and serially after each interval, rereads the bounded password file on each attempt, verifies the archive before pruning only reserved scheduled filenames, and joins cancellation before storage shutdown. Manual archives and the newly verified archive are retained. Success logs include the completion time and archive basename; failures emit a sanitized operation error and retry after the interval. The private destination must have mode 0700; the password file must deny group/other access and cannot itself be a symlink. Demo mode never starts this worker. Optional `SUBLANE_BACKUP_WEBHOOK_URL` sends one bounded `backup_failure` JSON event per failed attempt to an operator-configured public HTTPS destination, separately from workspace alert permissions; delivery failures are logged without URLs. The notification carries no private filesystem path or error text. Configuration is deployment-owned; remote uploads and a browser scheduling form are not implemented.


Authenticated account, resource-group and personal-key model dialogs include discovered hidden capabilities with a localized “Hidden model” label after visible models, preserving alphabetical order within each group, including hidden-only catalogs and search results. Group and key catalogs apply the existing resource policy before exposing hidden metadata; a permitted visible route keeps a shared model visible without changing its public owner metadata. Client model discovery and CC Switch picker suggestions remain filtered, and inference authorization, quota and availability checks are unchanged. Internal quota details remain hidden from usage presentation.

Grok Build model discovery reads the authenticated subscription catalog and preserves hidden entries as callable native model capabilities. Entries marked `hidden` or `_meta.hidden` are labeled in authenticated browser model catalogs but omitted from client model lists and picker suggestions; picker aliases resolve to the advertised routing model. Explicit HTTP and WebSocket calls retain existing authorization, account lifecycle, capacity, cooldown and allowance checks. Older catalogs refresh automatically to acquire subscription capabilities and visibility metadata.

Administrators can manually test a discovered model from a subscription account or API channel's model catalog. Each test sends a fixed generation prompt through that resource's credentials and proxy, shares gateway/account/model admission, and ends after 30 seconds or cancellation. Results show successful output, elapsed time, or a sanitized failure reason in the current dialog. Tests consume upstream quota independently of resource-group routing and member allowances, retain no prompt or response content, and create no conversation affinity or member request history. Synthetic tests cover all supported providers; live provider acceptance remains separately unverified.

Personal usage on the overview supports an optional API Key filter. Totals, daily/model/resource-group breakdowns, detail tables, and hourly activity share the selected key and period. Choices load on demand from paginated personal key metadata and include revoked keys. Queries enforce session ownership and workspace scope; allowances, request limits, and team usage remain independent. Daily and hourly aggregates persist the key dimension for 90 days in the same transaction as request history. An additive migration preserves earlier unattributed aggregates in the all-key view and records a separate key collection start; older usage is not reconstructed from bounded request history.

General → Model prices (`/pricing`) gives administrators and members a read-only view of the current merged global pricing catalog. It lists input, cached input, and output reference rates in USD per million tokens with source labels, model search that trims whitespace and ignores case, and 50-row pagination. Reload failures retain the last loaded catalog with a warning. The session-protected `GET /api/pricing` denies anonymous requests. These prices support request cost estimates and new allowance revisions; existing revisions debit using saved rates. A listed price does not guarantee model access or represent actual subscription charges. The offline demo returns an empty catalog without fetching prices or opening normal pricing files.

Request history and usage pages export UTF-8 CSV through the same authenticated, workspace-scoped JSON reads used by the interface. Request exports walk descending cursors with current filters, cap output at 5,000 retained requests, preserve personal account redaction and stop on workspace/identity changes. Usage exports preserve the selected reporting period, totals, daily rows and existing top-20 breakdowns with coverage counts and UTC metadata. Unreported token values are blank; reference costs remain estimates. Text fields are quoted and formula-prefixed values are neutralized for spreadsheet import. Downloads are bounded, cancel on unmount, and never contain prompts, responses or credentials.


An allowance revision uses current pool-model prices when available. If a supported model has no current catalog price, the revision reuses its own previously saved price when one exists; otherwise that model cannot pass allowance admission. Price-coverage warnings are derived from the current catalog and each revision's saved rates when read, rather than persisted with the revision. A restored catalog price clears its warning; a model absent from the saved rates remains blocked until a new priced revision takes effect. Saving fails only when no usable model price remains. For an active time-window allowance, configuration edits take effect at the next boundary of its longest current window, potentially up to 365 days away; the edit form shows that effective date before saving. Pausing or enabling access remains immediate.

Claude credentials persist one encrypted device identity per account across authorization, token rotation, reauthorization, and restart. Legacy credentials acquire that identity before provider IO, and failed persistence prevents execution. Subscription token adapters require explicit credential error codes before marking reauthorization necessary and preserve bounded upstream retry deadlines. These paths have synthetic coverage; live subscription and desktop-client acceptance remain separately unverified.

Subscription quota snapshots support Codex, Claude usage windows and Antigravity per-model remaining fractions and reset times. Reads use metadata endpoints only, preserve unknown fields and share the persisted cache, account lifecycle checks, bounded refreshes and safe failure states. Antigravity lists show three models by default, prioritize constrained models and expand on demand. Codex reset cards remain provider-specific. Fresh main quota windows gate Codex and Claude account admission. Antigravity gates only the exact requested model, including SDK thinking suffix normalization; it never blocks unrelated models or its whole account. Traffic warms the shared bounded cache for eligible pool accounts without awaiting provider IO. Unknown, stale, future-dated and already-reset data does not imply exhaustion. Existing conversations retain their account binding when quota is exhausted. Live provider acceptance remains separately unverified.

Codex reset cards support opt-in per-account once/daily/weekly schedules and explicit-quota-exhaustion triggers, with a shared configurable daily cap (default one), manual use, and bounded execution history. Two process-owned workers serve idle workspaces without browser activity. Requests persist an idempotency key before redemption; ambiguous results block new attempts until an administrator replays the same key. Eligibility and reset scope remain provider-controlled. Civil schedules follow the instance time zone, skip nonexistent DST times and runs missed by more than five minutes, and never backfill historical occurrences. Quota revisions fence observations made before redemption. Demo mode exposes read-only settings and starts no automation. Synthetic verification does not establish live redemption acceptance.

Role-aware activation guides account verification, pool access, personal keys, and the first successful generation. An optional floating tour highlights existing page controls, supports back/next/skip, yields to dialogs, and gates advancement on server-confirmed progress. Active walkthrough state is scoped to the browser tab, user, role, and workspace; it never marks server completion by itself. Completion is stored on the workspace membership with request accounting, independently of bounded request history. Personal key configuration guides use that key's model catalog without automatically revealing its secret. Failed request details provide role-appropriate recovery guidance.

Workspace administrators may opt into generic JSON webhooks for account reauthorization, pools with no verified enabled non-cooling supported subscription account, and elevated generation failures. Notifications are disabled by default. The process-owned alerts service polls local persisted state, encrypts destinations per workspace, and persists incident deduplication, bounded delivery retries, and recovery events. It never executes inference, includes prompt/response content, or reports quota snapshots as guaranteed capacity. Only public HTTPS destinations are supported. Explicit test notifications are bounded to one per workspace per minute with a persisted cooldown and do not change incident state. Optional model-unavailable and used-quota-threshold alerts reuse local gateway capacity snapshots. Unknown/stale observations retain existing incidents rather than claiming recovery; saturation alone is excluded.

Enabled workspace webhooks also report settled member allowance usage at fixed 80% and 95% thresholds, reusing accounting-owned current windows, member overrides, ratio limits and workspace access. Unknown pending exposure is not treated as settled usage, and unlimited/disabled/inaccessible allowances are skipped. The observer is bounded to 4,096 threshold observations per workspace and retains incidents when accounting observation fails. Stable per-recipient/window/threshold state stores the active revision/reset cycle, deduplicates across restart and rearms for a new period without adding one historical row per cycle. Webhook metadata contains local scheme/member/window/threshold identifiers and the revision/reset cycle; no names, credentials or content. A data-preserving migration expands the alert kind constraint and adds the cycle marker. This is an administrator webhook notification, not direct member email or monetary billing.

An opt-in server demo (`SUBLANE_DEMO=true`) uses a fresh temporary database, public demo credentials, synthetic accounts and usage, and an offline provider transport. It reuses normal authentication and management views, blocks all mutations except login/logout and all gateway transports, and cleans up its temporary data on graceful shutdown. The normal data directory and pricing files are not opened. Demo login and authenticated views explicitly label the data as illustrative; production instances continue to use real data only.

Workspace administrators can configure optional outgoing content rules at `/admin/content`. Checks default to off, support case-sensitive literal terms and Go RE2 expressions, and use one workspace-wide observe or block mode. Saved matching content is encrypted with workspace-bound vault encryption and never returned in metadata; editors can retain existing content without revealing it. Sample testing is local and does not retain samples or call a model. All generation protocols check decoded JSON strings, including duplicate fields, before account leases or provider IO; WebSocket turns check rebuilt context and local prewarm before retention. Checks are bounded to 50 rules, 1,024-byte patterns, 8 MiB of JSON and 64 nesting levels. Observe mode forwards unchanged content and marks incomplete checks; block mode rejects matches and incomplete checks. Request diagnostics retain only mode, policy revision, rule IDs and failure state. Policy changes are transactionally audited. Startup and backup verification require the original key and validate all encrypted workspace policies. Images, binary content and deliberately encoded secrets are not decoded; content replacement, client bypasses and per-hit external notifications are not implemented.

Gateway resilience uses a validated, immutable startup policy per workspace: capacity defaults to 128, account wait queues to 100 requests/30 seconds, and request/turn deadlines to 30 minutes. Account/member concurrency controls support up to 1,000 while preserving existing saved limits and default values. Explicit temporary HTTP rejections can retry on the original account before a successful response, retaining one observation/settlement and rechecking access before each attempt. Request deadlines and unknown network failures do not penalize account health. Explicit 5xx/invalid-stream failures use durable account/model counting windows and cooldowns; actual upstream 429s retain their rate-limit deadlines. HTTP SSE has serialized comment keepalive and optional upstream-event idle deadlines, and inference header waits are separate from metadata transport. Existing conversation affinity remains unchanged. These paths use synthetic coverage; live provider and workload acceptance remains separate.

Optional quota-weighted account rotation is enabled by `SUBLANE_GATEWAY_QUOTA_WEIGHTED=true` at startup and defaults to off. After every existing policy, quota, allowance, cooldown and concurrency check, new/unbound conversations rotate in proportion to the most constrained remaining main-window percentage, rounded up to 1–100 slots. Weighting applies only when every candidate in the winning preference tier has fresh numeric windows and the same supported subscription provider; mixed providers, unknown, stale or partial observations retain equal rotation. Antigravity weights use only the exact requested model. Existing conversation bindings and parent-account preferences remain authoritative. Weights are a percentage-based scheduling heuristic, not an estimate of comparable absolute plan capacity or guaranteed remaining requests.


SDK execution and streaming failures emit bounded structured diagnostics correlated with the SubLane request and local account IDs. Diagnostics distinguish the observed HTTP status from the SDK error status, including failures after HTTP 200, and retain failure stages, network categories, allowlisted error codes/types and validated upstream request IDs. Raw error messages, credentials, URLs and prompt/response content are excluded; unknown error labels become `unknown`. Failure diagnostics are visible at the default log level, while cancellation diagnostics remain at debug level. Request history and accounting retain their existing metadata-only contract.

Optional process-wide Prometheus text exposition is served at `/metrics` only when `SUBLANE_METRICS_TOKEN` supplies a separate 32–128 character visible ASCII bearer credential. Authentication applies before method/path handling; browser sessions, gateway keys and query-string credentials do not grant access. The shared bounded collector counts gateway observations once across HTTP and WebSocket turns, including local rejections and persistence failures, and survives workspace runtime eviction. Counters and fixed histograms reset on process restart. Fixed outcome labels, duration/known-first-output histograms, active inference leases and queued-request gauges expose no workspace/member/account/model names, request IDs, content or secrets. Scrapes read memory only and never initiate provider IO or SQL. Disabled installations retain no collector, and demo mode does not enable metrics. No new runtime dependency is added.

Gateway uploads renew a 30-second idle read deadline when bytes arrive, with a five-minute total upload bound and the existing request-size and concurrency limits. The read deadline is cleared before generation. Upload timeouts return HTTP 408 with `request_body_timeout`; other read failures return `request_body_read_failed`. Authenticated upload, HTTP parsing and WebSocket normalization rejections are retained in existing request history with consistent request IDs, original timing and no upstream account, token charge or cooldown penalty. Bounded metadata persistence survives client cancellation. Unauthenticated traffic and connection-level handshake rejections remain operations diagnostics. Structured logs retain fixed failure stages/reasons, received/declared byte counts and WebSocket connection limits without logging request content or caller-supplied model/session values. The dashboard localizes upload failures and recovery guidance in every supported language.

Gateway admission allows model changes with reasoning, compaction and reconstructed WebSocket history when the current bound account remains usable and supports the requested model. WebSocket continuation identity survives normalization so rebuilt transcripts cannot authorize account migration. Complete portable history may still replace an unsupported binding; a durable rebind marker protects older model-scoped state after recorded account moves, legacy-scope adoption and restart. Additive migration 019 preserves existing bindings and treats their current account as the continuity baseline; earlier account moves cannot be reconstructed. Incompatible model continuations return HTTP 409 with `conversation_model_conflict`, distinct from an unavailable account binding, and request history and every supported language provide model-specific recovery guidance. Live provider and desktop acceptance remain separate.

## Brand Commitments

The name is SubLane. Black, white, and neutral grays form the primary palette. Success, warning, error, and information states may use semantic colors. Preserve the previously agreed palette and Shadcn Admin components; keep the interface minimal and restrained.

## Product Principles

- Keep deployment simple and avoid unnecessary runtime dependencies.
- Complete real connection workflows before broadening the feature set.
- Separate upstream credentials from member gateway keys.
- Validate resource budgets with measurements rather than presenting targets as guarantees.

Grok Build uses the pinned SDK's xAI executor through the subscription chat proxy. Administrators can authorize a Grok account using a session-bound device-code flow or import a CLIProxyAPI `type: "xai"` OAuth JSON export. Device polling is bounded, paced, cancellable and single-use. SubLane owns encrypted credentials and token refresh; execution auth explicitly selects OAuth and never contains refresh tokens or imported endpoint overrides. Model discovery reads the account's xAI catalog. Grok quota reporting reads the official CLI subscription billing endpoint, preserving unknown usage, weekly/monthly reset windows and the shared persisted cache. Included legacy credits may supply a percentage when the modern period is absent; on-demand spending, prepaid balances and product breakdowns are never treated as subscription allowance. Quota-based admission supports Codex and Claude main windows and exact Antigravity models, but not Grok. Grok client version policy checks the official npm latest stable tag every six hours, retains the last successful version across failures and restarts, and permits platform-owner manual pins. The same version snapshot supplies inference and billing identity headers. Grok media endpoints are not implemented. Synthetic tests cover credential persistence, device authorization, refresh, model discovery, HTTP/SSE and Responses WebSocket routing; real subscription and desktop-client acceptance remain unverified.

Model-scoped limits are owned by the gateway. Explicit structured Antigravity limits matching the requested native model persist with account lifecycle and manual-resume revisions; unknown 429 responses retain account-wide cooldown. Recovery uses one admitted normal request per model, with no extra inference probe. An unrelated or older successful request cannot clear a newer failure, failed writes retain a bounded closed state in memory, and reauthorization/enablement changes invalidate old limits. The SDK Antigravity cooling override delegates its local timer to this durable owner. Account cards report limited model counts without labeling the entire account unhealthy; scheduling settings clear both scopes. Upstream HTTP 403 reports permission denial rather than requesting credential reauthorization. Live subscription acceptance remains separately unverified.

Pool and personal-key model dialogs provide local model eligibility snapshots with observation clocks, aggregate exclusion reasons and known retry times. Administrator pool views include account details; personal-key views always redact subscription identities. Reads reuse catalog/quota/runtime admission rules without provider IO, capacity leases or affinity changes. Unknown capabilities remain distinct from known unavailability; request-specific member/key/allowance admission and existing conversation bindings remain authoritative.

Claude client version policy checks the official Claude Code npm stable tag every six hours, independently of Codex and Grok. Manual pins take priority and failed checks retain the persisted version. Public SDK bootstraps provide immutable per-version Claude executors without retaining additional listeners or credentials; requests already in flight retain their version snapshot. User-Agent and billing metadata are generated by the SDK before CCH signing. Opus 5.5 and Sonnet 5.5 requests use their supported adaptive thinking and effort controls while preserving explicit output limits. OpenAI none maps to low effort for Opus and between-tools thinking for Sonnet; native unsupported manual thinking budgets or forced tool choices are rejected locally. Live subscription acceptance requires separate verification.
